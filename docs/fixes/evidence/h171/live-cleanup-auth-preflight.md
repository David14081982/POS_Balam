# H171 — lector previo al retiro de Auth

Apoyo del informe único H171. `h171-live-cleanup-auth-preflight.mjs` prepara y valida una lectura; no crea conexiones, no ejecuta DML, no llama a GoTrue y no abre el certificador. Pendiente de commit.

`buildAuthCleanupPreflightSql({plan,catalog,sourceUrl,storageOwnerColumns?})` recibe el plan de la jornada, las 64 tablas del catálogo canónico y la URL exacta de BALAM. Importa las 18 FK revisadas de `h171-auth-retirement.mjs`; el catálogo Storage conocido es `AUTH_PREFLIGHT_STORAGE_COLUMNS` (owner y owner_id en buckets y objects). La consulta también descubre todas las columnas actuales de propiedad: una columna nueva bloquea el contrato hasta revisar su cobertura. Admite la identidad principal y, si existe con procedencia demostrada, una segunda identidad de cuenta. No inventa una segunda cuenta para completar un número fijo.

La transacción es REPEATABLE READ, READ ONLY, UTC/ISO y devuelve conteos directos por identidad para las 18 FK, referencias lógicas POS y columnas Storage; ausencia de cobertura no equivale a cero. Incluye los 64 hashes completos por tabla, catálogo POS y dependencias Auth, censo y hash de Auth ajeno, estado y FULL hash de la solicitud protegida 7054, contexto real y filas exactas del alcance SQL que permanezcan. Las contraseñas, correos, metadatos completos y cuerpos de filas no salen: sólo hashes, UUID y los marcadores específicos del run.

`validateAuthCleanupPreflight({input,plan,catalog,sourceUrl,storageOwnerColumns?,baseline?})` devuelve `{preflight,readOnly,ready,blockers,certified:false,cleanupVerified:false}`. El controlador debe rechazar `ready:false`. `preflight` usa nombres snake_case, incluyendo `pos_fingerprints`, `protected_request` y `snapshot_revision`. `source_url` identifica el origen Supabase; `executor_source_url` conserva la URL de ejecución validada. La respuesta queda vinculada a proyecto/run/actor/build/artefacto/plan y al respaldo previo de identidades Auth.

El contrato de revisión se obtiene de las FK y triggers reales y exige la definición H166 registrada: cinco acciones SET NULL y dos CASCADE provocan siete invalidaciones por retiro Auth, aun con cero hijos POS. El lector devuelve valor, hash completo, hash del resto de campos, `delta_per_delete:7` y SHA del contrato. No atribuye avances a una intención durable. El adaptador que posee el journal de retiro y la observación de ausencia comprueba el incremento exacto; los otros 63 hashes, Auth ajeno y la solicitud protegida permanecen exactos. No se rebobinan contadores ni se permite actividad real concurrente por interpretar «cero QA» como una autorización para sobrescribirla.
